# Sikka 1.0 Syntax Contract audit

**Issue:** [#3](https://github.com/ws-rush/sikka/issues/3)
**Audited revision:** `19bc591`
**Scope:** `README.astro-syntax.md` compared with the parser, both compiler targets, public API, and focused tests. This records evidence only; it does not classify any behavior for 1.0 or recommend removal.

## Method and baseline

The parser produces one AST for both render targets (`src/index.ts:231-236`); sync and streaming then use the same emitters, with the streaming target substituting a buffer and component-boundary yields (`src/compiler.ts:1410-1420`, `src/compiler.ts:1578-1593`). Focused streaming coverage exercises directives, elements, spreads, components, slots, and expressions (`test/api.test.ts:826-1048`), and one complex sync/stream equality case exists (`test/api.test.ts:493-508`).

`nub run test` was run in this isolated worktree. It executed 400 tests: 398 passed; the Zod test failed because this worktree cannot resolve the declared dev dependency (`test/syntax-06-astro-global.test.ts:100-106`, `package.json:45-56`). The test's failure is environmental, not evidence that the template syntax failed. All other findings below are source- and focused-test-backed.

## Existing behavior absent from the reference

These are current behaviors, not proposed contract additions.

- **Public rendering surface and injected I/O:** `Sikka.renderString`, `render`, `streamString`, `stream`, compilation, component registration, and cache invalidation are public (`src/index.ts:68-163`). File rendering requires caller-provided `readFile` and optional `views` (`src/index.ts:182-266`), and the API tests cover paths, cache, direct compiled functions, registration, and file imports (`test/api.test.ts:67-363`). None is described in the syntax reference.
- **Runtime options affecting syntax output:** `varName`, `autoEscape`, `autoFilter`/`filterFunction`, `aggregateAssets`, and `debug` are public options (`src/types.ts:13-36`) with sync coverage at `test/api.test.ts:394-437` and streaming coverage at `test/api.test.ts:590-630`. In particular, `aggregateAssets: true` suppresses script/style output rather than collecting it (`src/compiler.ts:754-765`; test `test/api.test.ts:610-617`).
- **`Astro.slots` helper API:** generated `Astro.slots` has `render(name)` and `has(name)` in addition to the documented `Astro.props` (`src/compiler.ts:473-487`). The reference does not mention either.
- **Streaming-only async frontmatter:** the streaming target is an async generator and has focused `await` frontmatter tests (`test/api.test.ts:789-821`). The synchronous target is made with `new Function` (`src/compiler.ts:377-393`), so the same syntax cannot be synchronous. This is both undocumented behavior and a cross-runtime divergence.
- **Syntax/output normalizations:** `Fragment` and `<>` both erase their wrapper; native void elements output ` />`; non-void self-closing elements output open/close pairs; HTML comments are raw output; script/style contents are raw text. See `src/compiler.ts:789-817`, `src/parser.ts:326-394`, and tests `test/syntax-03-elements-components.test.ts:7-72`, `:161-254`.
- **Additional parser and import shapes:** the import collector records default, named, namespace, combined, and aliased import clauses, skips `import type`, and does not filter by extension (`src/parser.ts:120-195`). The reference documents only default `.astro` examples.
- **Diagnostics beyond the reference's inline “Error” comments:** unclosed fences/tags/expressions/comments/assets/slots/strings/attribute values, malformed openings/attributes, missing file readers/files, unresolved/circular imports, and debug runtime wrapping are tested at `test/syntax-07-errors.test.ts:6-131` and produced by `src/parser.ts:91-104`, `:384-409`, `:697-721`, `:777-881`, and `src/index.ts:237-251`.

## Intentional rejections and diagnostics already present

These are implementation/test facts; they are not a decision that the resulting diagnostics are the desired 1.0 contract.

- Fragment ordinary attributes and directives are rejected at compile time, except `slot`, `set:html`, and `set:text` (`src/compiler.ts:863-915`); focused tests cover `id` and `is:raw` (`test/syntax-03-elements-components.test.ts:73-79`).
- `is:raw` on `Fragment` is a parse error (`src/parser.ts:718-755`), covered at `test/syntax-04-directives.test.ts:229-234`.
- `set:html` with `set:text`, `set:html` with children, and `set:text` with children throw during compilation (`src/compiler.ts:1166-1186`); the first two are covered at `test/syntax-04-directives.test.ts:198-204`. The reference marks the first two (`README.astro-syntax.md:310-314`), but does not mention the `set:text`-children case.
- Structural malformed input yields `ParseError`, and compile resolution errors yield `CompileError` through the public API (`src/index.ts:231-251`), with the detailed test matrix at `test/syntax-07-errors.test.ts:6-131`.

## Semantic ambiguities requiring later contract decisions

1. **Cross-runtime guarantee boundary.** Shared emitters give strong parity for covered syntax, but async frontmatter works only in streaming (`test/api.test.ts:789-821`), while component dispatch differs (`renderSync` versus awaited callable: `src/compiler.ts:1410-1420`). The reference states no sync/stream scope or exception.
2. **Attribute merging and falsy semantics.** With a spread, classes/styles are accumulated and ordinary keys use last-write semantics (`src/compiler.ts:1025-1149`); without one, repeated `class`/`class:list` or `style` attributes are emitted separately (`src/compiler.ts:931-1023`). The reference says “Combining” (`README.astro-syntax.md:267-269`, `:287-289`) but does not specify a single merged attribute. Non-spread dynamic `false` becomes `disabled=""` through `__escape` (`src/compiler.ts:1001-1005`), whereas spread `false`/`null` is omitted (`src/compiler.ts:1141-1145`).
3. **Raw/trust boundary.** Ordinary interpolations escape, `set:text` escapes, `set:html` concatenates values without escaping, and `RawHtml` bypasses escaping (`src/escape.ts:29-45`, `src/compiler.ts:1189-1215`). The reference calls out XSS only in an example (`README.astro-syntax.md:325-326`), not the complete trust model or public construction path for `RawHtml` (it is not exported by `src/index.ts`).
4. **Frontmatter language and import contract.** The AST calls frontmatter “JS/TS” (`src/types.ts:28-31`), but runtime evaluation is JavaScript `new Function` (`src/compiler.ts:377-393`) and only imports/exports are stripped. The prose restriction to `.astro` is neither extension-enforced nor a diagnostic. `SikkaOptions.resolvePath` is public (`src/types.ts:18-19`), but component resolution uses the compiler-local resolver (`src/compiler.ts:302-331`) rather than that option.
5. **Components versus HTML/custom elements.** Capitalized tags are treated as component candidates (`src/compiler.ts:789-804`), but unknown candidates fall back to literal HTML (`src/compiler.ts:1423-1456`); a capitalized identifier whose value is a string produces that string tag. The reference does not define naming, unknown-tag, or dynamic-tag behavior.
6. **Slot presence versus rendered content.** Any supplied child, including `null`, `undefined`, empty string, or empty Fragment, installs a slot key before its rendered content is known (`src/compiler.ts:1355-1378`), thereby suppressing fallback. The reference shows several examples but does not state this rule.
